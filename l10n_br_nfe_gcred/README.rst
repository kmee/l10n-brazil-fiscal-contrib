This module reports the ICMS presumed credit of the NF-e items in the
``gCred`` group of the product (fields ``cCredPresumido``,
``pCredPresumido`` and ``vCredPresumido``, up to 4 groups per item),
created by NT 2019.001 v1.60 and named ``gCred`` (I05g) by v1.62.

The benefit code and the percentage are set on the product, per company
(each company belongs to one state, and the code is the one granted by
that state, the same code used in the EFD). The fiscal document lines of
the product get one group with that code and percentage, and the amount
is the percentage applied to the ICMS base of the line. The group is
updated when the product or the ICMS base of the line changes, and other
groups can be typed on the line. Incoming NF-e keep the groups of the
supplier XML.

Before the NF-e is issued, the module refuses what the schema rejects:
more than 4 groups per item, a code that is not 8 or 10 characters long
without spaces, or a percentage out of the 0 to 999 range.

Configuration
=============

On the product form, *Fiscal* tab, fill the *Presumed Credit Code* and
the *Presumed Credit (%)* of the company in use.

Usage
=====

Issue the NF-e as usual. The fiscal document line shows the groups in
the *Presumed Credit* tab, where they can be changed or completed, and
the NF-e XML carries the ``gCred`` tags of the item.

Known issues / Roadmap
======================

- Rules I05g-10 (the state allows the group) and I05h-10 (the code is
  valid in the state table), created by NT 2019.001 v1.63 and v1.64, are
  applied by each state at its discretion against its own tables and are
  not checked here.
- The amount is the percentage applied to the ICMS base of the item.
  When the state rule uses another base, change the amount on the line.
- The percentage keeps 2 decimals on the line (the spec field), while
  the layout accepts up to 4.
- The product holds a single code per company; the other groups of an
  item (up to 4) are typed on the line.
- The groups are shown on the fiscal document line form; the invoice
  line form (``l10n_br_account``) does not show them yet.

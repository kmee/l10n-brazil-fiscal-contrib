Abstract models of the Electronic Electricity Bill (``NF3e``,
``model 66``), generated from the official XSD schemas of the NF3e
Portal.

The module does not issue the NF3e: it is the base of ``l10n_br_nf3e``,
which injects these mixins into the fiscal document
(``l10n_br_fiscal.document``) and its lines, following the same pattern
as the OCA modules ``l10n_br_nfe_spec``, ``l10n_br_cte_spec`` and
``l10n_br_mdfe_spec``.

The models cover the NF3e layout 1.00 with the IBS and CBS group of the
tax reform, in the version of the schema package
``PL_NF3E_1.00a_NT2026.002_RTC_1.01`` (NT 2026.002 RTC v1.01), which is
the one shipped with ``nfelib`` 3.3.0.

Generation
----------

The files in ``models/v1_0`` were generated by
`xsdata-odoo <https://github.com/akretion/xsdata-odoo>`__ 1.2.2 from the
schemas that `nfelib <https://github.com/akretion/nfelib>`__ keeps in
``nfelib/nf3e/schemas/v1_0``, starting from the root schema
``nf3e_v1.00.xsd`` (which brings in ``nf3eTiposBasico``,
``DFeTiposBasicos`` and ``tiposGeralNF3e``):

.. code:: bash

   git clone https://github.com/akretion/nfelib
   cd nfelib
   export XSDATA_SCHEMA=nf3e
   export XSDATA_VERSION=10
   export XSDATA_LANG="portuguese"
   export XSDATA_CURRENCY_FIELD=brl_currency_id
   export XSDATA_SCHEMA_NOTE="PL_NF3E_1.00a_NT2026.002_RTC_1.01"
   export XSDATA_HEADER=$'Copyright 2026 KMEE\nLicense AGPL-3.0 or later (https://www.gnu.org/licenses/agpl).'
   export XSDATA_SKIP='gConsumidor\.tpPosTar(Injet)?$'

   xsdata generate nfelib/nf3e/schemas/v1_0/nf3e_v1.00.xsd \
     --package nfelib.nf3e.odoo.v1_0 \
     --output=odoo

The ``nf3e_v1_00.py`` file comes out empty (the root schema only
declares the ``NF3e`` element) and is not included in the module.

``XSDATA_SKIP`` removes the ``tpPosTar`` and ``tpPosTarInjet`` fields of
the ``gSCEE/gConsumidor`` group: in the schema they are lists of simple
values (a repeated sequence of ``enerAloc`` and ``tpPosTar``), which the
generator would turn into a ``One2many`` to a model that does not exist.
The ``competApur`` tags (type ``xs:gYearMonth``) are also left out,
because the generator does not map that type yet.

Field prefix
------------

Each field has the prefix of the schema and two digits of the version:
``nf3e10_``. A minor layout revision (1.00a, 1.01) uses the same fields;
a major version would have new fields and tables.

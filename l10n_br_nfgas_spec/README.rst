Bindings Python e modelos abstratos da Nota Fiscal Eletrônica do Gás
(``NFGas``, ``modelo 76``), gerados a partir dos esquemas XSD oficiais
do Portal NFGas (SVRS).

O módulo não emite a NFGas: é a base do ``l10n_br_nfgas``, que injeta
estes mixins no documento fiscal (``l10n_br_fiscal.document``) e nas
suas linhas, no mesmo desenho do ``l10n_br_nf3e_spec``. Como a
``nfelib`` 3.3.0 não tem a NFGas, os bindings ficam aqui, no pacote
``bindings``, até irem para a ``nfelib`` (ver o roteiro).

Esquemas
--------

Pacote ``PL_NFGas_NT2026.004 RTC_1.01`` (leiaute 1.00 do MOC NFGas 1.00g
com a NT 2026.004 RTC v1.01, que traz o grupo ``IBSCBS`` obrigatório no
item e o valor líquido ``vItemLiq``/``vProdLiq``), publicado em
30/10/2026 na página de documentos do Portal NFGas
(``https://dfe-portal.svrs.rs.gov.br/NFGAS/Documentos``):

- endereço:
  ``https://dfe-portal.svrs.rs.gov.br/NFGAS/DownloadArquivoEstatico/?sistema=NFGAS&tipoArquivo=2&nomeArquivo=PL_NFGas_NT2026.004%20RTC_1.01.zip``
- sha256 do zip:
  ``bc2e83ea5c9021177ab6156404bbbfcffab5ce49bc0486487fbbadeae86dd0b1``

Os arquivos do zip estão em ``schemas/v1_0``. Os ganchos de formatação
do repositório trocam o fim de linha do zip (CR e CRLF) por LF e
acrescentam a quebra de linha final; o conteúdo dos esquemas é o
publicado.

Bindings (``bindings/v1_0``)
----------------------------

Gerados com o xsdata 25.7 pelo ``generate_bindings.py`` e pelo
``.xsdata.xml`` da `nfelib <https://github.com/akretion/nfelib>`__ 3.3.0
(com os patches de geração da ``nfelib/generate_patches``), o mesmo
processo dos bindings ``nfelib.nf3e``. A configuração difere da
``nfelib`` em três pontos:

- ``RelativeImports`` ligado, porque os bindings vivem dentro de um
  módulo Odoo;
- as classes ``Tnfgas``, ``TprotNfgas``, ``NfgasProc`` e ``EvCancNfgas``
  recebem o ``nfelib.CommonMixin`` (assinatura, serialização e
  validação), como as equivalentes da NF3e;
- a tag ``imposto/TxReg`` vira o atributo ``txReg`` (substituição de
  campo, como a ``Comp`` do CT-e), porque o grupo tem uma classe
  aninhada com o mesmo nome e o padrão do campo passaria a ser a classe.

.. code:: bash

   git clone https://github.com/akretion/nfelib
   cd nfelib
   # no .xsdata.xml: <RelativeImports>true</RelativeImports>, as quatro
   # extensões <Extension type="class" class="^Tnfgas$" import="nfelib.CommonMixin" .../>
   # e <Substitution type="field" search="^TxReg$" replace="txReg"/>
   mkdir -p schemas/v1_0  # com os xsd do zip
   python generate_bindings.py nfgas  # alvo nfgas: schema_dir schemas/v1_0,
                                      # package l10n_br_nfgas_spec.bindings.v1_0

Os dados do pacote de esquemas ficam neste arquivo, e não no
``bindings/v1_0/__init__.py`` como na ``nfelib``, porque o gancho
``check-docstring-first`` do repositório recusa o bloco de metadados. O
``.ruff.toml`` das pastas geradas só libera o tamanho de linha (padrões
e rótulos longos do esquema).

Modelos (``models/v1_0``)
-------------------------

Gerados pelo `xsdata-odoo <https://github.com/akretion/xsdata-odoo>`__
1.2.2 a partir do esquema raiz:

.. code:: bash

   export XSDATA_SCHEMA=nfgas
   export XSDATA_VERSION=10
   export XSDATA_LANG="portuguese"
   export XSDATA_CURRENCY_FIELD=brl_currency_id
   export XSDATA_SCHEMA_NOTE="PL_NFGas_NT2026.004_RTC_1.01"
   export XSDATA_HEADER=$'Copyright 2026 KMEE\nLicense AGPL-3.0 or later (https://www.gnu.org/licenses/agpl).'

   xsdata generate schemas/v1_0/nfgas_v1.00.xsd \
     --package nfelib.nfgas.odoo.v1_0 \
     --output=odoo

O ``nfgas_v1_00.py`` sai vazio (o esquema raiz só declara o elemento
``NFGas``) e não entra no módulo. As duas tags ``competApur`` (tipo
``xs:gYearMonth``) ficam de fora, porque o gerador ainda não mapeia esse
tipo.

Prefixo dos campos
------------------

Cada campo leva o prefixo do esquema e de dois dígitos da versão:
``nfgas10_``. Uma revisão menor do leiaute usa os mesmos campos; uma
versão maior teria campos e tabelas novos.

Known issues / Roadmap
======================

- Levar os bindings e os esquemas da NFGas para a ``nfelib``
  (``nfelib/nfgas/bindings/v1_0`` e ``nfelib/nfgas/schemas/v1_0``, com a
  entrada no ``CHANGELOG_SCHEMAS.md`` e no ``generate_bindings.py``) e
  passar este módulo a importar de lá, como o ``l10n_br_nf3e_spec``.
  Depois disso o pacote ``bindings`` e a pasta ``schemas`` saem daqui.
- Regerar quando o Portal NFGas publicar um pacote de esquemas novo (NT
  2026.001 RTC de vinculação de pagamento já está dentro do pacote da NT
  2026.004).
- Mapear o tipo ``xs:gYearMonth`` no xsdata-odoo para gerar as tags
  ``competApur``.
